# RFC 0018: Последовательный конвейер миграций базы данных (Sequential Migration Pipeline)

Статус: Implemented  
Версия ядра: 0.6.0+

---

## Реализовано

### 1. Архитектура и принципы
- **Автономный конвейер без внешних тяжелых CLI**: отказ от Alembic и внешних утилит в рантайме дистрибутива FerrumOS для сохранения минимального размера бинарника (`~3.65 МБ`).
- **Служебный журнал `_schema_migrations`**:
  - `version` (INTEGER PRIMARY KEY) — строго монотонный номер версии (1, 2, 3...).
  - `name` (VARCHAR) — уникальное имя миграции.
  - `app_version` (VARCHAR) — версия релиза, в котором появилась миграция.
  - `applied_at` (TIMESTAMP) — время применения.
- **Атомарность и автоматический бэкап**:
  - Запуск в хуке `@on_startup` до начала обработки сетевых запросов.
  - Автоматическое создание страховой копии файла БД: `ferrum.db.bak_v{app_version}_{timestamp}`.
  - Выполнение всех непримененных миграций внутри единой транзакции базы данных.
- **Бесшовный скачок через версии (Multi-Version Skip)**:
  - При обновлении с любой старой версии (например, `v0.6.2` сразу до `v0.7.12`) все промежуточные шаги накатываются строго последовательно от младшей к старшей.

---

### 2. Спецификация реестра миграций

```python
# tools/ferrum/migrations.py
MIGRATION_PIPELINE: List[Migration] = [
    Migration(
        version=1,
        name="initial_schema",
        app_version="0.6.0",
        sql="-- Initial v0.6.0 baseline"
    ),
    # Future steps:
    # Migration(2, "add_wifi_channel_to_nodes", "0.6.2", sql="ALTER TABLE nodes ADD COLUMN wifi_channel INTEGER DEFAULT 1;"),
]
```

## Планируется

1. **Интерфейс аудита миграций в FerrumOS Studio**:
   - Отображение истории примененных миграций и резервных копий в панели настроек системы.
2. **Точки отката (Rollback snapshots)**:
   - Кнопка быстрого восстановления базы данных из созданного `.bak` файла прямо из UI Studio в один клик при диагностике ошибок.
