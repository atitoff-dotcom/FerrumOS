    🧭 RFC-0006: FerrumCanvas / FerrumTouch — Визуальный No-Code конструктор дашбордов для мобильных и настенных экранов¶

    Метаданные Значение
    Номер RFC-0006
    Название FerrumCanvas & FerrumTouch: Визуальный No-Code конструктор дашбордов и легковесное PWA для смартфонов и настенных планшетов
    Статус Draft / Accepted
    Автор FerrumOS Core Team
    Дата создания 2026-09-05
    Целевые платформы iOS Safari (PWA Standalone), Android Chrome (PWA), Настенные Android/Linux планшеты (Kiosk Mode), Десктопные браузеры
    Связанные модули ferrum-hub (WASM ядро), ferrum-runner, tools/ferrum/frontend, rfcs/0004

    🎯 1. Введение и Проблематика¶

    1.1. Контекст¶

    FerrumOS обеспечивает надежное управление на уровне микроконтроллеров с детерминированным временем отклика (< 1 мс), а FerrumOS Studio предоставляет профессиональную среду разработки для инженеров (IDE, мониторинг GPIO, компилятор, логи).

    Однако для повседневной эксплуатации конечными пользователями (семьей, операторами, нетехническими специалистами) критически необходим быстрый, интуитивный и эстетичный пульт управления со смартфонов и настенных планшетов.

    1.2. Анализ недостатков существующих решений (Home Assistant Lovelace и аналоги)¶

    В существующих платформах (Home Assistant, OpenHAB) создание визуальных интерфейсов сопряжено с серьезными барьерами: 1. YAML-ад и разрозненность: Чтобы получить современный вид панелей, пользователь вынужден устанавливать сторонние плагины через HACS (mushroom-cards, bubble-card, card-mod, stack-in-card, layout-card) и писать сотни строк YAML со сложными Jinja-шаблонами и CSS-костылями. 2. Хрупкость при обновлениях: Регулярные обновления ядра ломают сторонние кастомные карточки, стили «съезжают», консоль заполняется ошибками. 3. Отсутствие настоящего Touch-ориентированного редактора: В HA редактирование карточек ориентировано на десктоп с глубокими вложенными модальными окнами. Переместить или изменить плитку пальцем на планшете крайне неудобно. 4. Технические идентификаторы вместо названий: Пользователь вынужден искать датчики по нечитаемым системным именам вроде sensor.esp32c6_adc_gpio_1_val. 5. Низкая производительность на настенных планшетах: Тяжелый веб-стек (Shadow DOM, LitElement, полифиллы) приводит к нагреву и лагам анимаций на доступных настенных планшетах (Rockchip, Allwinner, Fire HD).

    🏛️ 2. Концепция FerrumCanvas: Принцип «Touch & Play»¶

    Вся система визуального управления в FerrumOS разделяется на две взаимосвязанные части: * FerrumTouch: Легковесная клиентская среда исполнения (PWA) для смартфонов и настенных планшетов с частотой отрисовки 60 FPS, тактильным откликом и задержкой отклика < 20 мс. * FerrumCanvas: Интерактивный WYSIWYG-конструктор, встроенный прямо в интерфейс без переключения в сложную инженерную IDE.

    2.1. Ключевые принципы простоты сборки¶

    1. Живой Drag & Drop пальцем:
    2. Долгое нажатие (1 секунда) на любую плитку переводит экран в режим редактирования (карточки мягко покачиваются, визуализируя готовность к перемещению).
    3. Пользователь перемещает плитку пальцем — соседи плавно расступаются на адаптивной сетке (Smart Magnetic Grid).
    4. Растягивание за угол пальцем меняет размер плитки (1×1 компактная кнопка, 2×1 широкая плашка со слайдером, 2×2 детальный блок).
    5. Добавление в 3 касания без кода:
    6. Нажатие [ + ]:
      • Шаг 1: Выбор категории (💡 Свет, 🔌 Розетка, 🌡️ Климат, 🪟 Шторы, 🔘 Сценарий, 📊 Датчик, 📹 Камера).
      • Шаг 2: Выбор устройства из списка с понятными человеческими именами («Люстра в гостиной», «Теплый пол»).
      • Шаг 3: Выбор размера и иконки в один клик.
    7. Zero-Click Onboarding (Самоописывающаяся аппаратура из Fluent JS):
    8. В отличие от традиционных систем (ESPHome + Home Assistant), где разработчик сначала пишет прошивку контроллера, а затем вручную создает сущности и верстает карточки в Lovelace, в FerrumOS код микроконтроллера сам описывает свое визуальное представление: 
      const chandelier = GPIO.output(14)
    .name("Люстра")
    .room("Гостиная")
    .icon("lightbulb")
    .initial(false);

const floor = Sensor.temp(1)
    .name("Теплый пол")
    .room("Ванная")
    .unit("°C");
    9. Бинарный манифест ноды (Node Manifest, ~60–100 байт): При компиляции скрипта в байткод компилятор формирует компактную таблицу экспорта периферии. При первом же старте контроллера манифест отправляется по FRP на хаб/PWA.
    10. Автогенерация комнат и карточек: PWA мгновенно создает комнату «Гостиная» и размещает готовую интерактивную плитку со слайдером или переключателем. Ноль ручной работы!
    11. Двусторонняя реактивность (Live Binding):
      • Физическое нажатие кнопки на стене мгновенно подсвечивает плитку в PWA через WebSocket/FRP за < 20 мс.
      • Свайп по плитке на смартфоне мгновенно меняет ШИМ или состояние выхода на кристалле.
    12. Никакого YAML и CSS:
    13. Конфигурация интерфейса сериализуется в чистый плоский JSON (dashboard.json).
    14. Карточки стилизованы профессионально «из коробки» (поддержка тем: Minimal Dark, Apple Light, Glassmorphism, Cozy Home).

    🧩 3. Каталог встроенных стандартных виджетов (Core Cards)¶

    Интерфейс не требует сторонних расширений — все базовые сценарии умного дома закрываются встроенным набором карточек:

    Виджет Размеры Функциональность
    SwitchCard (Свет / Розетки) 1×1, 2×1 Одиночный тап — переключение вкл/выкл; долгое удержание — открытие детальной шторки (таймер автоотключения, энергопотребление).
    DimmerCard / RGBWCard 2×1, 2×2 Плавный горизонтальный слайдер яркости; в режиме 2×2 — круговая палитра цвета и выбор цветовой температуры (CCT).
    ClimateCard (Термостат) 2×2 Круговой радиальный регулятор целевой температуры, текущая температура и влажность, селектор режимов (Авто / Обогрев / Эко / Выкл).
    CoverCard (Шторы / Жалюзи) 2×1, 2×2 Кнопки Вверх / Стоп / Вниз, процентный слайдер открытия ламелей или полотна.
    SensorSparklineCard 1×1, 2×1 Крупное значение (CO₂, температура, давление, мощность Вт) с легким графиком тренда за 24 часа без тяжелых аналитических библиотек.
    SceneButtonCard 1×1 Запуск сценария («Ушел из дома», «Кино», «Спокойной ночи») с тактильной анимацией нажатия и статусом исполнения.
    CameraCard 2×2, 3×2 Живое превью видеопотока (WebRTC / MSE / Snapshot JPEG) с быстрым открытием на весь экран по клику.
    WallClockWeatherCard 4×1, 3×2 Информационный блок для настенных экранов: текущее время, день недели, погодный виджет и сводный статус дома (кол-во включенных ламп, открытых окон).

    📟 4. Специализированный режим настенного экрана (Kiosk Mode)¶

    Для стационарных планшетов, монтируемых в стену, реализована нативная поддержка специфики постоянного использования:

    1. Web Wake Lock API:
    2. Блокировка отключения дисплея в активное время суток без необходимости рутования планшета или установки сторонних приложений вроде Fully Kiosk Browser.
    3. Энергосберегающий скринсейвер (OLED/IPS Screensaver):
    4. При отсутствии активности пользователя или людей в комнате экран переходит в режим приглушенных ночных часов с низкой яркостью для защиты матрицы от выгорания.
    5. Бесконтактное пробуждение:
    6. Интеграция с локальными датчиками движения, радарами присутствия (mmWave) через FerrumHub или через встроенную фронтальную камеру планшета (детекция движения в кадре на чистом WebAssembly).
    7. PIN-код для критических функций:
    8. Защита открытия дверей, снятия с охраны и доступа к настройкам цифровым кодом прямо на экране.

    ⚡ 5. Архитектура и Производительность¶

    5.1. Технологический стек¶

    • Фронтенд-ядро: Svelte 5 (Runes) — отсутствие виртуального DOM, компиляция в прямой ультра-быстрый JS.
    • Стилизация: Tailwind CSS 4 — минимальный размер CSS бандла (< 25 КБ).
    • Сетевой транспорт: WebSocket поверх бинарного протокола FRP / JSON-RPC с мгновенной доставкой событий (< 20 мс).
    • PWA & Офлайн: Service Worker с Local-First кэшированием всех ресурсов; приложение открывается мгновенно даже при временном отсутствии связи с хабом.
    • Тактильный отклик: Нативная микровибрация (navigator.vibrate([15])) при взаимодействии с переключателями на смартфонах.

    5.2. Формат конфигурации (dashboard.json)¶

    Конфигурация хранится в лаконичном, человекочитаемом виде:

    {
  "version": 1,
  "theme": "glass_dark",
  "rooms": [
    {
      "id": "living_room",
      "name": "Гостиная",
      "icon": "sofa",
      "cards": [
        {
          "type": "switch",
          "title": "Люстра",
          "entity": "living/light_main",
          "size": "1x1",
          "icon": "lightbulb"
        },
        {
          "type": "climate",
          "title": "Климат",
          "entity": "living/thermostat",
          "size": "2x2"
        }
      ]
    }
  ]
}

    🗺️ 6. План внедрения (Этапы реализации)¶

    1. Этап 1: Клиентский движок FerrumTouch (Svelte 5):
    2. Базовая разметка PWA (Web Manifest, Standalone режим, адаптивный Grid).
    3. WebSocket-коннектор к реактивной шине FerrumHub (state.get / state.set).
    4. Этап 2: Базовый комплект карточек (Core Cards):
    5. Реализация Switch, Dimmer, Climate, Sensor Sparkline, Scene.
    6. Этап 3: Интерактивный режим редактирования FerrumCanvas:
    7. Модуль Touch Drag-and-Drop (нативные Pointer Events без тяжелых внешних библиотек).
    8. Изменение размеров карточек, диалог добавления в 3 шага.
    9. Этап 4: Настенный Kiosk Mode:
    10. Screensaver, Web Wake Lock, интеграция с датчиками присутствия.
    11. Этап 5: Автосборка комнат (Zero-Click Onboarding):
    12. Синхронизация с метаданными нод FerrumOS и автогенерация комнат.

    📊 7. Сравнение подходов¶

    Критерий Home Assistant Lovelace Apple Home / HomeKit FerrumCanvas / Touch
    Сложность сборки Высокая (YAML, HACS, CSS) Жестко задана Apple Zero-Code Touch Drag-and-Drop
    Автосборка комнат Требует ручной правки Частичная Автоматическая из кода ноды
    Скорость на планшетах 20–40 FPS (тяжелый DOM) Высокая (только iOS) 60 FPS (Svelte 5, ультралегкий)
    Кастомизация Через card-mod (хрупко) Отсутствует Встроенные темы без CSS-кода
    Поддержка Kiosk Нужен сторонний софт Нет Нативный Kiosk Mode из коробки
