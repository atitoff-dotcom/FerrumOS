    🧭 Roadmap: GPIO Входы и Обработка Сигналов в FerrumOS¶

    Этот документ содержит пошаговый трекер развития цифровых входов (GPIO Inputs), фильтрации сигналов, антидребезга, реактивных прерываний, умных кнопок и счетчиков импульсов в операционной системе FerrumOS.

    📊 Статус реализации по этапам¶

    Этап Компонент Статус Приоритет
    Этап 1 Базовая схемотехника и прямое чтение (pull, invert, gpio.read) 🟢 Готово P0 (Критический)
    Этап 2 Конвейер фильтрации и антидребезг (debounce, delayed_on/off) 🟢 Готово P1 (Высокий)
    Этап 3 Реактивное ожидание фронтов (Zero-CPU wait_edge & Edge-to-IPC) 🟡 Следующий P1 (Высокий)
    Этап 4 Умные кнопки и жесты (click, double_click, long_press, release) 🟢 Готово P2 (Средний)
    Этап 5 Аппаратный счетчик импульсов (pulse_counter, расходомеры, тахометры) ⚪ Запланировано P2 (Средний)
    Этап 6 Квадратурный инкрементальный энкодер (rotary_encoder) ⚪ Запланировано P3 (Низкий)

    🏛️ Архитектурные принципы и паттерны использования¶

    • Для простых единичных задач (например, мигнуть тестовым диодом):
    • Проще и быстрее написать всё в одном файле в линейном стиле.
    • Для реальной автоматизации и умного дома (кнопки, реле, датчики, шторы, вытяжки):
    • Event-Driven IPC на порядок надежнее, чище и масштабируемее:
      • Изоляция сбоев: падение или ошибка в одном скрипте не роняет другие процессы.
      • Горячее обновление: логику реле или подсветки можно обновлять по воздуху без перезапуска драйверов кнопок и контроллера.
      • Минимальный оверхед: каждая микро-задача весит всего ~350–450 байт RAM.
    • Строгая локальность и приватность (Local-First & No-Leak):
    • Внутренняя шина ipc работает исключительно локально в памяти чипа (задержка ~2 мкс).
    • Автоматической скрытой отправки в сеть или MQTT НЕТ. События уходят в сеть только при явном вызове mqtt.publish() разработчиком.
    • Zero-Buffer Signal для кнопок и датчиков (без очередей и переполнений):
    • Для кнопок и дискретных событий используется модель мгновенного сигнала / актуального состояния (Zero-Buffer Signal):
      • Расход RAM = 0 байт буфера очереди.
      • Задачи-подписчики мгновенно пробуждаются за доли микросекунды.
      • Отсутствуют задержки («запоздалые клики») и переполнения FIFO-очередей.
    • Буферизованные очереди (FIFO Queue) резервируются только для потока данных (UART, GPS, Modbus пакеты).
    • Гибкая маршрутизация событий (Локально + Сеть):
    • Поддерживаются все 3 способа отправки наружу:
      1. Прямой вызов: ipc.publish(...) локально + mqtt.publish(...) наружу.
      2. Флаг дублирования: events.emit("alarm/fire", 1, { mqtt: true }) — отправляет в IPC и копирует в MQTT.
      3. Паттерн «Скрипт-Шлюз»: отдельный микро-скрипт подписывается на важные локальные ipc.on(...) и форвардит их в mqtt.publish(...).
    • Гибридная обработка множества событий в одном скрипте (events.wait + .on()):
    • Синхронный events.wait([btn, timer, "ipc/topic"]): для линейных сценариев и конечных автоматов.
    • Декларативный btn.on("click", ...), ipc.on(...) + events.loop(): для событийного JS-стиля.
    • Оба стиля одинаково поддерживают аппаратные пины, таймеры и межскриптовые события из других скриптов без динамических аллокаций памяти.

    Этап 1. Базовая схемотехника и прямое чтение (Pin Config & Direct Polling)¶

    Цель: Надежная аппаратная инициализация входных пинов с выбором подтяжки и логической инверсией.

    • [x] Упаковка флагов конфигурации в 1 байт байткода (OP_BIND_GPIO):
    • direction = 0 (Input)
    • pull: none (00), up (01, ~45 кОм к 3.3V), down (10, ~45 кОм к GND)
    • invert: логическая инверсия для кнопок, замыкающих на GND (1 = нажато)
    • [x] Поддержка в компиляторе (ferrum-compiler & compiler.py):
    • gpio.mode(pin, { direction: "input", pull: "up", invert: true })
    • gpio.input(pin, { pull: "up", invert: true })
    • [x] Чтение состояния в виртуальной машине и ядре (OP_GPIO_READ):
    • Чтение аппаратного уровня из регистра/пинов чипа ESP32-C6.
    • Применение флага invert на уровне ядра (возврат 1 при замкнутой на GND кнопке).
    • Методы в JS: gpio.read(pin), gpio.is_high(pin), gpio.is_low(pin).

    Этап 2. Конвейер фильтрации сигналов и антидребезг (Signal Filtering Engine)¶

    Цель: Автоматическое подавление дребезга механических контактов и наводок без нагрузки на пользовательский JS-код.

    • [x] Антидребезг (debounce_ms: 25):
    • Игнорирование дребезга и всплесков напряжения в течение заданного интервала (5..50 мс) после первого фронта.
    • [x] Задержка включения (delayed_on_ms: 100):
    • Переход в состояние ON только при стабильном удержании активного уровня не менее N мс (защита от ложных помех на длинных проводах герконов и концевиков).
    • [x] Задержка выключения (delayed_off_ms: 500):
    • Удержание состояния ON и переход в OFF только после N мс неактивности (для PIR-датчиков движения и плавного отключения).
    • [x] Симметричный фильтр (delayed_on_off_ms: 50) для тяжелых реле и индуктивных датчиков.
    • [x] Автоматический импульсный сброс (auto_off_ms: 200) для дверных звонков и импульсных кнопок.

    Этап 3. Реактивное ожидание фронтов (Zero-CPU Edge Wait & Edge-to-IPC)¶

    Цель: Мгновенная реакция на нажатие кнопки без постоянного polling-опроса в цикле.

    • [ ] Опкод OP_GPIO_WAIT_EDGE(pin, edge_type, timeout_ms):
    • Фронты: rising (0 -> 1), falling (1 -> 0), change / both (любое изменение).
    • Скрипт переходит в статус WaitingGpioEdge (0% CPU) и не потребляет ресурсы процессора.
    • Аппаратное прерывание ESP32-C6 IO_MUX мгновенно будит задачу.
    • [ ] Генератор IPC-событий (gpio.on_change):
    • Автоматическая публикация в шину событий ОС при изменении пина: 
      gpio.on_change(9, { topic: "btn/hall", edge: "falling", debounce_ms: 30 });
    • [ ] Zero-Buffer Signal передатчик событий:
    • Использование модели передачи без очереди (0 байт буфера, мгновенное пробуждение, отсутствие лагов и переполнений для дискретных кнопок).

    Этап 4. Умные кнопки и распознавание жестов (Smart Button & Multi-Click)¶

    Цель: Управление устройствами через одну кнопку (клики, дабл-клики, удержание).

    • [x] Детектор жестов в ядре (ButtonDetector & OP_CONFIG_BUTTON, OP_BUTTON_READ, OP_BUTTON_WAIT):
    • click — одиночный короткий клик (< 350 мс).
    • double_click — двойной клик с паузой между нажатиями < 250..300 мс.
    • long_press / hold — длинное удержание кнопки (> 800..1000 мс).
    • release — отпускание кнопки после удержания.
    • [x] JS API для умных кнопок: 
      let btn = gpio.button(9, { pull: "up", debounce_ms: 25, long_press_ms: 800 });
let event = btn.wait(); // "click" | "double_click" | "long_press" | "release"

    Этап 5. Автономные счетчики импульсов (Pulse Counter & Pulse Meter)¶

    Цель: Точный учет расхода воды, газа, электроэнергии и измерение скорости вращения (RPM).

    • [ ] Фоновый счетчик в ядре Rust (PCNT / GPIO ISR):
    • Накопление счетчика в фоне на аппаратном уровне (до сотен тысяч импульсов/сек).
    • Аппаратный ВЧ глитч-фильтр filter_us (1..100 мкс) для отсечения наводок от электромоторов.
    • [ ] Метрики расхода:
    • gpio.pulse_count(pin) — чтение суммарного накопленного объема.
    • gpio.pulse_rate(pin) — мгновенная частота импульсов (имп/сек или литры/мин).
    • [ ] pulse_meter:
    • Измерение точного интервала времени между соседними импульсами для сверхмедленных датчиков (анемометры, капельный расход).

    Этап 6. Квадратурный инкрементальный энкодер (Rotary Encoder)¶

    Цель: Регулировка параметров вращающимися ручками (громкость, температура, меню).

    • [ ] Декодер фаз A/B (pin_a, pin_b):
    • Квадратурный декодер с подавлением дребезга.
    • [ ] JS API for Encoder: 
      let knob = gpio.encoder(4, 5, { min: 0, max: 100, step: 1, initial: 50 });
let val = knob.read();
