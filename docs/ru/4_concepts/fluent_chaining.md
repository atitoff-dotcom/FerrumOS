# Стандарт Fluent Chaining

В FerrumOS вся инициализация периферии и настройка выводов микроконтроллера строго следуют паттерну **Fluent Chaining (цепочка вызовов методов)**.

```javascript
// Атомарная конфигурация цифрового выхода
const relay = GPIO.output(15)
    .openDrain(true)
    .pullUp()
    .invert(true)
    .initial(false);
```

---

## ⚡ Проблема построчной императивной настройки

В традиционных embedded-фреймворках пины часто настраивают построчно:

```javascript
// ❌ ЗАПРЕЩЕНО в FerrumOS — ведет к аппаратным глитчам
const relay = GPIO.output(15);
relay.open_drain = true;    // Перезапись регистра 1
relay.pull_up = true;       // Перезапись регистра 2
relay.initial = false;      // Глитч! Пин на мгновение зависает в воздухе
```

### Почему построчная мутация опасна:
1. **Аппаратные глитчи на пинах**: При пошаговой перезаписи регистров пин может на несколько микросекунд оказаться в плавающем или неверном состоянии. Это приводит к ложному срабатыванию реле, открытию MOSFET-ключей или сбросу внешних микросхем.
2. **Множественные прерывания и циклы RMW**: Каждое присваивание вызывает отдельный вызов ядра и цикл чтения-модификации-записи (Read-Modify-Write) аппаратного регистра.
3. **Состояние частичной инициализации**: Если скрипт упадет в середине настройки, пин останется в неопределенном промежуточном состоянии.

---

## 🛡️ Атомарная инициализация через Fluent Chaining

FerrumOS полностью устраняет паразитные импульсы: цепочка методов воспринимается компилятором и ядром как **единая атомарная спецификация**.

Когда вы вызываете методы по цепочке:
1. Вызовы `.openDrain()`, `.pullUp()`, `.invert()`, `.initial()` собирают компактный дескриптор в регистрах виртуальной машины.
2. Аппаратные регистры RISC-V микроконтроллера записываются **атомарно за один такт**.
3. Пин переходит из безопасного высокоомного состояния (Hi-Z) прямо в заданный рабочий режим без промежуточных скачков напряжения.

---

## 📐 Правила Fluent Chaining

1. **Единая цепочка при объявлении**:
   Всегда настраивайте подтяжки, инверсию и начальное состояние в одной непрерывной строке/выражении.
2. **Запрет конфигурационных объектов**:
   Не передавайте словари настроек `{ openDrain: true }`. Цепочка методов дает 100% автодополнение в IDE и проверку типов на этапе компиляции.
3. **Неизменяемость после привязки**:
   После инициализации пин работает в заданном режиме. Для смены режима переинициализация выполняется также атомарной цепочкой.
