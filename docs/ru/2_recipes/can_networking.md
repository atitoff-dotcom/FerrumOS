# Рецепт: Распределенная сеть CAN-шины

`Статус: 🟢 Stable (v5.1)` • `Чип: ESP32-C6 / ESP32-C3 (TWAI)` • `С версии: FerrumOS 5.1` • [RFC-0001 (Шина CAN)](../rfcs/0001-can-distributed-bus.md)

> [!NOTE]
> **Текущая готовность:** Аппаратная передача кадров CAN 2.0B / TWAI, неблокирующие кольцевые очереди Zero-Copy и распределенные реактивные сигналы (`state.signal().can()`, `.urgent()`) поддерживаются на ESP32-C6 и ESP32-C3 с аппаратным модулем TWAI и задержкой реакции ~0.2 мс по витой паре.

В этом руководстве описано объединение нескольких автономных плат FerrumOS по витой паре **CAN / TWAI**. Сигналы между платами передаются за 0.2 миллисекунды даже при полном отключении Wi-Fi, роутеров или серверов.

---

## 1. Топология сети

```text
 ═════════════════════════════ CAN-шина (Витая пара CAN-H / CAN-L, 250 kbps) ═════════════════════════════
          │                                              │                                      │
          ▼                                              ▼                                      ▼
 ┌─────────────────────────┐            ┌─────────────────────────┐            ┌─────────────────────────┐
 │ Узел A: Выключатель     │            │ Узел B: Блок реле       │            │ Узел C: Шлюз            │
 │ (ESP32-C6 / TWAI)       │            │ (ESP32-C6 / TWAI)       │            │ (Wi-Fi + CAN Шлюз)      │
 └─────────────────────────┘            └─────────────────────────┘            └─────────────────────────┘
```

На обоих концах физической линии CAN обязательно должны быть установлены терминаторы **120 Ом**.

---

## 2. Передающий узел (Выключатель)

Узел-источник связывает нажатие кнопки с распределенным сигналом. 29-битный идентификатор CAN компилятор рассчитывает автоматически по хэшу топика:

<!-- snippet: id="can_bus_setup" category="Шины данных (I2C / SPI)" title="CAN Bus (TWAI) Сеть" icon="fa-network-wired" desc="Инициализация распределенной шины CAN 2.0B на 250 kbps." badges="['CAN 2.0B', 'TWAI']" -->
```javascript
// Настройка шины CAN на стандартных пинах ESP32-C6 (TX=21, RX=22)
CAN.bus()
    .pins(21, 22)
    .baud(250000);

// Настройка кнопки на плате A
const btn = GPIO.input(9)
    .pullUp()
    .button()
    .clickMs(350);

// Распределенный реактивный сигнал, синхронизируемый по шине CAN
const light = state.signal("hallway/light", false).can();

while (true) {
    const event = btn.wait();
    if (event === Button.CLICK) {
        // Переключение распределенного сигнала по шине CAN
        light = !light;
    }
}
```

## 3. Принимающий узел (Исполнительное реле)

Плата исполнительного реле подписывается на распределенный сигнал и переключает физический выход:

```javascript
// Настройка шины CAN на плате B
CAN.bus()
    .pins(21, 22)
    .baud(250000);

// Атомарная настройка реле на плате B
const relay = GPIO.output(12)
    .openDrain(true)
    .pullUp()
    .invert(true)
    .initial(false);

// Реакция на распределенный сигнал шины CAN
const light = state.signal("hallway/light", false).can();
light.watch((on) => {
    relay.write(on);
});
```

## 4. Однопроводной режим (без внешнего трансивера)

Для компактных выключателей в подрозетниках и миниатюрных датчиков FerrumOS поддерживает **однопроводной режим (Single-Wire CAN)**. В этом режиме контроллер работает без микросхем трансиверов (SN65HVD230 / TJA1050):

```text
  ESP32-C6 (Плата A)                        ESP32-C6 (Плата B)
  ┌────────────────┐                       ┌────────────────┐
  │         GPIO21 ├───┬───────────────┬───┤ GPIO21         │
  │                │   │    1 провод   │   │                │
  │            GND ├───┼───────────────┼───┤ GND            │
  └────────────────┘   │  сигнала      │   └────────────────┘
                     ┌─┴─┐
                     │ R │ (Подтяжка 4.7 кОм к 3.3V)
                     └─┬─┘
                      3.3V
```

### Аппаратная схема
- **Линия**: 1 провод данных между GPIO плат + общий провод GND.
- **Подтяжка**: один резистор 4.7 кОм между линией данных и 3.3V.
- **Скорость**: 25 kbps (оптимально для емкости открытого стока до 20 метров).

<!-- snippet: id="can_single_wire" category="Шины данных (I2C / SPI)" title="Single-Wire CAN (1 провод)" icon="fa-bolt" desc="Однопроводная шина без внешнего трансивера на 25 kbps." badges="['Single-Wire', 'Zero-Transceiver']" -->
```javascript
// Однопроводная шина на GPIO 21 (25 kbps)
CAN.bus()
    .singleWire(21)
    .baud(25000);

// Явный номер сигнала (1) или автоматический порядковый номер
const light = state.signal("hallway/light", false).can(1);
```

### Сравнение: Дифференциальный vs Однопроводной CAN

| Параметр | Дифференциальный CAN (2 провода) | Однопроводной CAN (1 провод) |
| :--- | :--- | :--- |
| **Физический уровень** | Витая пара CAN-H / CAN-L | 1 провод данных + общий GND |
| **Трансивер** | Требуется (SN65HVD230 / TJA1050) | **Не требуется** (аппаратный Open-Drain) |
| **Согласование** | Терминаторы 120 Ом на концах линии | Один резистор 4.7 кОм к 3.3V |
| **Скорость** | 125 kbps – 1 Mbps (по умолчанию 250 kbps)| 10 kbps – 50 kbps (рекомендуется 25 kbps) |
| **Дальность** | До 1000 метров | До 15–20 метров |
| **Применение** | Магистраль дома / шкаф автоматики | Подрозетники, датчики, выключатели |

## 5. Преимущества архитектуры

1. **Полное отсутствие единой точки отказа**: Выключатели и реле работают аппаратно за 0.2 мс при зависшем сервере или обесточенном роутере.
2. **«Холодный чип» в щитке**: На узлах CAN-шины Wi-Fi модем отключается (`WiFi.mode(OFF)`), ток падает до 15 мА, чип не греется внутри закрытого щита.
3. **Детерминированный арбитраж**: Срочные сигналы (`.urgent()`) используют 0-й приоритет CAN, гарантируя мгновенную доставку даже при загрузке шины телеметрией.
