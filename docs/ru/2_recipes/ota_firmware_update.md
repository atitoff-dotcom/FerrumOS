# Рецепт: Обновление по воздуху (OTA) и Hot-Swap

`Статус: 🟢 Hot-Swap в релизе (v5.0) / 🟣 Dual-Boot ядра (Roadmap Этап 8)` • `Чипы: ESP32-C6, ESP32-C3`

> [!NOTE]
> **Текущий статус:**
> - **Hot-Swap байткода (Работает в v5.0)**: Мгновенное обновление задач из Studio или CLI за <100 мс без перезагрузки чипа и без потери состояния шин.
> - **Dual-Boot A/B ядра (Этап 8 Дорожной карты)**: Обновление бинарника ядра Rust по Wi-Fi запланировано на Этап 8 в [ROADMAP.md](https://github.com/atitoff-dotcom/FerrumOS).

В FerrumOS реализована двухуровневая модель обновления:
1. **Hot-Swap байткода**: Мгновенная замена логики скриптов за **< 100 мс** без перезагрузки чипа и без разрыва сетевых соединений.
2. **Dual-Boot A/B ядра**: Безопасное обновление бинарного образа операционной системы Rust по воздуху с автоматическим откатом при сбое.

---

## 1. Мгновенная замена байткода из Studio

При нажатии кнопки **Deploy** в FerrumOS Studio:
1. Компилятор собирает байткод (.fbc).
2. Байткод передается в пакете Wire Protocol (Кадр `0x03`).
3. Виртуальная машина останавливает выполнение задачи, подменяет буфер инструкций, сбрасывает указатели стека и возобновляет работу за доли миллисекунды.

---

## 2. A/B Dual-Boot обновление ядра

Для обновления бинарника операционной системы:
- **Раздел A**: Текущее рабочее ядро.
- **Раздел B**: Целевой раздел, куда записывается новый образ.

```bash
# Загрузка нового ядра через утилиту Ferrum CLI
ferrum ota-push --target 192.168.1.150 --firmware build/esp32c6_firmware.bin
```

### Защита от окирпичивания (Rollback)
1. После записи раздела B загрузчик выставляет флаг `STATE_PENDING_VERIFY`.
2. Чип перезагружается в новое ядро.
3. Ядро обязано пройти самодиагностику и вызвать `System.confirmBoot()` в течение 30 секунд.
4. При сбое, зависании или перезагрузке по сторожевому таймеру (Watchdog) аппаратный загрузчик автоматически возвращается в раздел A.
