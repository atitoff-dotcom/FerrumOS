# Архитектура системы и принципы проектирования FerrumOS

**FerrumOS** — это высокопроизводительная, модульная и отказоустойчивая микроядерная операционная система для микроконтроллеров (ESP32-C6 RISC-V, ARM Cortex-M), написанная на **Rust** с поддержкой динамического исполнения скриптов **JavaScript / Rhai** и подгружаемых WASM AOT модулей.

---

## ⚡ 1. Zero-Cost Сопрограммы (Неблокирующий ввод-вывод без ОС-потоков)

Ключевая инновация FerrumOS — отказ от тяжелых потоков FreeRTOS в пользу **кооперативных сопрограмм на базе конечных автоматов в ядре Rust**:

### Проблема традиционных RTOS:
* В классических RTOS (FreeRTOS, Zephyr) каждому потоку скрипта требуется выделять стек от 4 до 8 КБ RAM.
* При 10 параллельных скриптах автоматизации расходуется 80+ КБ драгоценной оперативной памяти только на стеки потоков.
* Переключение контекста (Context Switching) создает накладные расходы процессора.

### Решение FerrumOS:
1. **Прозрачность для разработчика (JS DX):**
   Разработчик пишет простой, синхронный, линейный код:
   ```javascript
   let line = device.uart("GPS").read_line(1000);
   delay_ms(500);
   ```
2. **Конечный автомат в ядре Rust (`enum ScriptExecutionState`):**
   ```rust
   pub enum ScriptExecutionState {
       Ready,
       WaitingTimer { wake_at: Instant },
       WaitingUart { timeout_at: Instant },
       WaitingQueue { channel: String, timeout_at: Instant },
       WaitingBus,
   }
   ```
3. **Мгновенный `yield`:**
   При вызове `delay_ms()` или ожидании данных с датчика скрипт замораживается и отдает управление в главный цикл ядра.
4. **Фоновые кольцевые буферы:**
   Аппаратные прерывания периферии (UART, I2C, SPI) складывают данные в `RingBuffer`. Как только данные поступают, ядро мгновенно пробуждает ожидающий скрипт.
5. **Экономия RAM:**
   10+ одновременно работающих скриптов укладываются всего в **~4–8 КБ RAM** вместо 80+ КБ.

## 🗄️ 2. Межскриптовое взаимодействие (IPC)

FerrumOS реализует микросервисную архитектуру прямо внутри микроконтроллера, разделяя задачи на независимые сервисы:

```
┌──────────────────┐       queue.send("telemetry")      ┌────────────────────────┐
│  Датчик DS18B20  │ ─────────────────────────────────► │  Термостат / Контроль  │
│ (Сборщик данных) │ ◄───────────────────────────────── │    (Логика работы)     │
└────────┬─────────┘       state.set("climate.temp")    └───────────┬────────────┘
         │                                                          │
         │ state.get("climate.temp")                                │ events.emit("alert")
         ▼                                                          ▼
┌────────────────────────┐                             ┌────────────────────────┐
│    MQTT / Web Cloud    │                             │  Сирена / Безопасность │
│   (Сетевая синхрон.)   │                             │  (Реактивные события)  │
└────────────────────────┘                             └────────────────────────┘
```

### Примитивы IPC:
1. **Шина общего состояния (`state` - Blackboard Key-Value Store):**
   - Потокобезопасное хранилище `Mutex<BTreeMap<String, Dynamic>>`.
   - Неблокирующее атомарное чтение и запись (`state.get`, `state.set`, `state.has`, `state.delete`).
   - Изоляция сбоев: падение одного скрипта не стирает накопленное глобальное состояние.
2. **Очереди сообщений (`queue` - FIFO Channel):**
   - Ограниченная кольцевая память (`Bounded Ring Buffer`, 16–32 сообщений на канал) с защитой от OOM.
   - Неблокирующее чтение `queue.receive(channel, timeout_ms)` с автоматическим переводом в режим ожидания.
3. **Шина событий (`events` - Pub/Sub):**
   - Реактивная передача дискретных уведомлений (`events.emit`, `events.on`).

## 🌐 3. Встроенный сетевой стек и Wi-Fi OTA Microkernel

В нативной прошивке (`crates/esp32c6-firmware`) интегрирован полностью автономный стек:

1. **`esp-wifi` + `smoltcp` (no_std):**
   - Подключение к точкам доступа Wi-Fi 802.11 b/g/n/ax.
   - Встроенный DHCP-клиент с автоматическим назначением IPv4 и маршрута по умолчанию.
   - Легковесный стек TCP-сокетов без накладных расходов libc/POSIX.
2. **Встроенный HTTP REST сервер (`crates/esp32c6-firmware/src/http_server.rs`):**
   - Работает на стандартном порту 80.
   - Обслуживает встроенный Glassmorphism Web Dashboard (`GET /`).
   - Предоставляет REST API для горячего управления скриптами:
     - `GET /api/scripts` — получение списка активных скриптов, их статусов и счетчиков выполнения.
     - `POST /api/scripts` — компиляция и запуск нового скрипта на лету.
     - `PUT /api/scripts/<id>` — атомарная замена кода без перезагрузки чипа.
     - `DELETE /api/scripts/<id>` — удаление скрипта и освобождение ресурсов.

## 🛡️ 4. Отказоустойчивость и супервизор (`ScriptSupervisor`)

1. **Лимит инструкций (`set_max_operations`):**
   Защита от бесконечных блокирующих циклов без вызова `delay_ms()`.
2. **Изолированный `Scope`:**
   Каждый скрипт работает в изолированном контексте переменных.
3. **Перехват паник и падений:**
   Необработанные ошибки переводят скрипт в статус `Failed`, записывают стек ошибки в лог и не влияют на работу сетевого стека и соседних скриптов.
4. **Аппаратная таблица владельцев пинов (`PinLockTable`):**
   Предотвращает одновременный конфликтный захват одного физического пина двумя разными скриптами.

## 🗂️ 5. Цифровой двойник (Digital Twin) и контекстная кросс-валидация

Для надежного управления парком микроконтроллеров без риска аппаратных конфликтов в FerrumOS реализована архитектура **Цифрового Двойника** на хосте:

```
storage/nodes/<node_id>/
├── device.json          # Паспорт чипа (модель платы, RAM, Flash, MAC, IP)
├── current/             # Актуальное зеркало работающих в RAM чипа задач
│   ├── state.json       # Манифест запущенных задач и карта пинов/шин
│   ├── blink_task.js    # Исходный код JS
│   └── blink_task.rhb   # Скомпилированный бинарный байткод
└── snapshots/           # Версионированные архивы слепков с функцией отката
    └── snapshot_<ts>_<label>/
```

### Контекстная Pre-Flight кросс-валидация (`validator.py`):
1. **Проверка коллизий пинов:** перед отправкой нового скрипта на плату сервер анализирует его требования к GPIO и сравнивает их с картой пинов уже работающих в памяти чипа задач.
2. **Разделяемые шины против монопольных пинов:**
   - Монопольные GPIO (реле, кнопки, RGB WS2812) не могут быть захвачены двумя разными задачами одновременно.
   - Разделяемые шины (I2C) разрешают использование одинаковых пинов SDA/SCL, но проверяют отсутствие конфликтов аппаратных I2C-адресов датчиков (например, BME280 `0x76` и OLED `0x3C`).
3. **Безопасное обновление:** при деплое задачи с тем же `Task ID` валидатор разрешает переиспользование пинов (Safe Self-Update).

## 📬 6. Межскриптовое взаимодействие (Inter-Script IPC)

В ядре ESP32-C6 реализован потокобезопасный брокер `IpcBus` (`crates/esp32c6-firmware/src/ipc.rs`):

1. **MPSC FIFO Очереди сообщений:**
   - Несколько задач-писателей могут публиковать события в именованный канал: `ipc.send("topic", val)`.
   - Задача-потребитель считывает сообщения в порядке поступления: `ipc.recv("topic")` или проверяет наличие: `ipc.available("topic")`.
   - Кольцевой буфер с ограничением емкости предотвращает переполнение оперативной памяти чипа.
2. **Глобальный реактивный стейт (Shared State Store):**
   - Сохранение и чтение актуальных показаний датчиков: `state.set("key", val)` и `state.get("key")`.
3. **Атомарная публикация (`ipc.publish`):**
   - Нативный опкод `OP_IPC_PUBLISH (0x25)` за 1 операцию отправляет сообщение в FIFO-очередь подписчиков **и** обновляет текущее значение в общем реестре состояний.
